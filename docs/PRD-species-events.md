## 1. 产品目标与背景

现有 App 用一套"狗本位"的固定 12 项事件服务所有宠物，导致大量非养狗用户的记录体验别扭甚至无法使用：养猫的人被迫点"遛狗"，养鱼/爬宠/鸟的人面对的是"遛狗/洗澡/摸摸/体重"等根本用不上的按钮，而真正需要的"换水/测水质/晒太阳/上手/出笼飞"无处可记。本次改动的目标是：**让每只宠物拥有一套与其物种贴合、且可由用户自行增删的速记事件集**，把产品从"狗的流水账"升级为"所有宠物的流水账"。

**三个正交的产品目标**：
1. **贴合（Relevance）**：按物种呈现正确的标签与事件——猫叫"外出"不叫"遛狗"，鱼有"换水/测水质"不出现"摸/遛/体重"。
2. **可裁剪（Personalization）**：预设之上支持用户隐藏用不到的按钮、并为兜底物种自建事件，速记区随个体习惯变清爽。
3. **不失真（Continuity）**：老用户的宠物、老记录、老备份在新体系下继续正确显示与统计，**不丢数据、不崩界面**。

## 2. 物种分类定义（核心）

宠物新增 `kind` 枚举，从 3 类扩展为 **8 类**（英文 key 作为存储值，中文名用于展示，emoji 为物种专属图标，用于物种选择器与事件矩阵分组，**不同于宠物头像 emoji**）。

| # | key | 中文名 | 物种 emoji | "人设"一句话 |
| --- | --- | --- | --- | --- |
| 1 | `dog` | 狗 | 🐕 | 高互动、需每日外出遛放的运动型伴侣。 |
| 2 | `cat` | 猫 | 🐈 | 室内为主、外出罕见；排泄需关注、爱玩逗猫棒。 |
| 3 | `rabbit` | 兔 | 🐇 | 室内笼养、需放风；爱啃咬但**不洗澡**（可局部清洁）。 |
| 4 | `bird` | 鸟 | 🐦 | 可观可互动；既能外出"遛鸟"，也能在家"出笼飞"。 |
| 5 | `fish` | 鱼 | 🐠 | 纯观察型，**无肢体互动**；核心是水质/换水/投喂。 |
| 6 | `rodent` | 鼠 | 🐹 | 小型啮齿类（仓鼠/豚鼠/龙猫等），需放风、浴沙、换垫料。 |
| 7 | `reptile` | 爬宠 | 🦎 | 冷血动物（龟/守宫/蛇/蜥）；需晒灯/晒背，无"外出"概念，可从饲养箱取出**上手互动**、会**蜕皮**。 |
| 8 | `other` | 其他 | ❓ | 兜底物种：罕见宠物或无合适分类者，事件全部由用户自定义。 |

> 物种 emoji 与宠物头像 emoji 是两层概念：物种 emoji 表达"这是什么动物"，宠物头像 emoji（现有 `EMOJI_OPTIONS`）表达"这只是谁"。新增宠物时选物种 → 自动带出物种 emoji 作为头像初值，用户仍可改成 🐩/🦜 等更个性化的头像。

- **基础事件（通用池）**：跨物种概念通用的候选事件，各物种**按需继承**（并非所有物种全都要，例如鱼的体检里不含"体重/便便/尿尿"）。

## 4. 自定义与隐藏机制（决策 ②）

### 4.1 隐藏机制 —— 建议**按宠物（petId）隐藏**

用户可隐藏某物种预设里自己用不上的按钮。**建议按 pet 维度存储隐藏列表**，理由：

1. **个体差异**：同种两只猫，一只玩逗猫棒、一只不玩；按物种隐藏无法区分。
2. **与现有模型一致**：App 本就是"选中一只宠物"（`activePetId`）的心智模型，隐藏天然属于"这只宠物"的偏好，改动最小。
3. **与自定义天然同构**："其他"物种的自定义事件本就按宠物归属（两只"其他"宠物可能是蛇和猪，差异极大），隐藏与其保持同一归属层更自洽。

**交互建议**：设置页新增"事件管理"区块——选择宠物 → 按"基础事件 / 专属事件"分组列出该物种预设，每项一个"显示/隐藏"开关；默认全部显示（即物种预设全集），用户做减法。为降低心智负担，可提供"恢复默认"一键还原。

> 备选方案：按物种全局隐藏（所有狗共享一套隐藏）。更简单但无法区分个体。**列为待确认项（§9）**。无论哪种，**"其他"物种的自定义事件均按宠物归属**。

### 4.2 自定义事件（仅 `other` 物种）

- **入口**：设置页"事件管理"→ 选择 `other` 宠物 → "＋ 新建自定义事件"。
- **emoji 来源**：复用并扩展现有 `EMOJI_OPTIONS` 选择器（8 列网格）；建议扩充一批常见宠物相关 emoji，供挑选。
- **名字**：1–6 个字符（约 6 个汉字），去首尾空格；**同宠物内不可重名**（避免歧义）。
- **颜色**：从预设色板中选（复用现有 Tailwind 主题色，如 emerald/amber/sky/rose…），或系统按创建顺序自动分配；**必须是 Tailwind 静态可扫描的完整 class 字符串**（沿用现有约束）。
- **字段**：默认带"备注（note）"；"是否计时"见 §9（建议 P2 支持）。
- **删除与边界**：见 §4.3。

### 4.3 数据存放与删除边界

- **存放（产品视角，具体方案由架构师定）**：新增独立的本地配置项（新 localStorage key，按 `petId` 归属）：
  - 隐藏配置：`{ [petId]: string[] }`（被隐藏的 type 列表）；
  - 自定义事件：`{ [petId]: [{ key, label, emoji, color, unit, fields }] }`。
  - 随导入/导出一起打包（沿用现有 `exportData`/`importData` 机制），保证换机不丢。
- **与记录关联**：事件记录仍只存 `type`（自定义事件用其 `key`）。渲染时**三级查找**：内置 type 索引 → 该宠物的自定义事件表 → 兜底 `other`。这样即使配置缺失也不会白屏。
- **删除自定义事件的建议**：**保留历史记录 + 渲染兜底，不连删**。理由：① 与现有"未知 type 兜底 `other`"的稳健行为一致，风险最低；② "配置"删除不应抹除用户已产生"数据"；③ 误删可恢复配置而不丢记录。
  - 为让删除后历史仍能显示原名，建议在事件写入时**冗余存一份 label 快照**（或用备注承载原 label）；若无快照则降级显示为"已删除的自定义事件"。
  - 是否提供"仅删按钮 / 连历史一起删"的二选一，见 §9。

## 5. 关键用户故事（User Stories）

1. **养猫用户**：作为养猫用户，我希望速记区看到"外出 / 便便 / 逗猫棒 / 剪指甲"，而不是"遛狗 / 拉屎"，这样标签不别扭、不用做心理翻译。
2. **养龟（爬宠）用户**：作为养龟用户，我希望有"晒太阳 / 上手互动 / 泡水喷水 / 蜕皮"，且不要出现"遛狗 / 洗澡"，这样能记录只有爬宠才有的行为。
3. **养鱼用户**：作为养鱼用户，我希望有"换水 / 测水质 / 清缸 / 观察异常"，且不出现任何"摸 / 遛 / 体重 / 便便"，因为鱼是纯观察型、没有肢体互动。
4. **讲究清爽的用户**：作为用户，我希望把用不到的按钮隐藏掉，让速记区只留我真正会点的几项，减少误点、提高记录速度。
5. **计时的用户**：作为用户，我希望给"外出 / 放风 / 出笼飞"记时长（开始→结束自动算），关掉 App 回来还能继续，并在统计里看到"本周外出总时长"。
6. **老用户**：作为老用户，我希望原来记的宠物和几千条历史记录在新版本里**照样显示、照样统计**，不需要重记，导出备份导入后也一致。
7. **兜底物种用户**：作为养了一只"蜜袋鼯/猪"的用户，我希望归到"其他"后能自己建事件（自选 emoji + 起名），不被固定选项限制。

## 7. 数据与迁移影响（产品视角）

> 本节只描述"产品层需要保证什么"，具体技术方案由架构师定。

### 7.1 宠物 kind 映射（老 → 新）

| 老 kind | 新 kind | 规则 |
| --- | --- | --- |
| `dog` | `dog` | 原样保留 |
| `cat` | `cat` | 原样保留 |
| `other` | `other` | 原样保留（**注意其事件集变化，见 7.3**） |
| 缺失 / 非法值 | `other` | 沿用现有"非法即兜底 `other`"策略 |

新增 `rabbit/bird/fish/rodent/reptile` 为**用户可选**，无老数据需要映射。

### 7.2 历史事件兼容（老记录不能崩）

- **全量保留现有 12 个 type**，不删除、不复用为别的语义；新增物种通过"**按物种裁剪显示 + label 覆盖**"实现，而**不是**删除老 type。因此：
  - 老 `type:'walk'` 记录：仍有效。若它属于一只 `kind:'dog'` 宠物，显示"遛狗"（不变）；若属于 `kind:'cat'` 宠物，**显示自动变为"外出"**——这是期望行为（老猫数据不会突然冒出"遛狗"）。
  - 老记录里出现"当前物种不该有"的 type（如给猫记过 `nailTrim`）：**照常显示**，因为物种专属 type 仍有全局默认定义，`getEventType` 也兜底 `other`。
- **导出/导入**：沿用现有 `exportData/importData` 的"未知字段忽略、按 id 去重"策略；新配置（隐藏/自定义）一并纳入备份，老备份（无这些字段）导入时**不报错**，用默认值补齐。
- **测试影响**：现有 `tests/eventTypes.test.js` 断言 `length === 12` 与固定顺序，架构师需同步改造测试（本次会改变事件定义的组织方式）。

### 7.3 需特别关注的迁移风险：`other` 用户按钮消失

老用户 `kind:'other'` 的宠物，在 v1.0 能看到全量 12 个按钮；若 v1.1 让"其他"物种**只剩自定义入口**，这些用户打开 App 会发现**按钮全没了**——这是体验倒退，违背"不能丢"的第 6 条用户故事（数据在但入口没了）。

**建议（二选一，倾向 A，待用户拍板 §9）**：
- **A.** "其他"物种默认展示**通用池兜底**（吃饭/喝水/便便/尿尿/体重/吃药/玩耍/摸摸/洗澡/备注）**＋ 自定义入口**，兼顾兜底与新需求；
- **B.** 迁移时为老 `kind:'other'` 宠物**回填一份默认事件集**，仍保留自定义入口。

## 8. UI 变化点（文字描述）

1. **新增 / 编辑宠物（SettingsView）**
   - `KIND_OPTIONS` 从 3 项扩为 8 项；物种选择改为带 emoji 的 chips / 分段控件（如 `🐕狗 🐈猫 🐇兔 🐦鸟 🐠鱼 🐹鼠 🦎爬宠 ❓其他`）。
   - 选定物种后，**自动把该物种 emoji 作为宠物头像初值**，用户仍可点开头像选择器换成 🐩/🦜 等个性化 emoji（保留现有 `EMOJI_OPTIONS` 交互）。
   - 编辑已有宠物时可改物种；改物种后其**可用事件集即时变化**（隐藏/自定义配置按 petId 保留，不因换物种而误删，但可能因物种变化而"暂时不可见"，需给出提示）。

2. **速记区（QuickLog）**
   - 取 `activePet.kind` 对应事件集 → 减去该宠物隐藏项 → 渲染按钮网格；按钮数量随物种自适应（仍是网格，行数自适应）。
   - 计时类事件按钮上可加"⏱"标识，点击后进入计时态（P1）。
   - 物种事件很少（如鱼 7 项）时排版自然留白；"其他"物种展示自定义事件 + 新建入口。

3. **编辑面板（EventEditor）**
   - 类型切换网格**按当前宠物物种过滤**；计时类显示"时长"，`poop` 显示性状/颜色等，逻辑沿用现有 `meta.fields` 驱动。
   - **兜底**：若被编辑的老事件 `type` 不在当前物种事件集内，仍需**保留该类型可选中/可显示**（避免"打开老记录却发现类型被吞"导致无法保存）。

4. **设置页（SettingsView）—— 新增"事件管理"区块**
   - 选择宠物 → 分组（基础 / 专属）列出预设事件，每项"显示 / 隐藏"开关（P1-1）。
   - "其他"宠物下提供"＋ 新建自定义事件"（emoji 选择 + 名字 + 颜色）与自定义列表的编辑/删除（P1-2）。
   - 提供"恢复默认（取消全部隐藏）"入口。

5. **统计页（StatsView）**
   - 把硬编码的"🐕 遛狗 / 💩 拉屎 / 🍚 吃饭"改为**按当前物种动态选择指标**：
     - "外出/放风"类图标与间隔卡片 → 文案随物种变化（狗"遛狗"、猫"外出"、鸟"遛鸟"…）；
     - 新增"**本周外出总时长**"与"最近一次外出时长"（P1-5，依赖计时数据）；
     - 对无对应事件的物种（如鱼无便便/无外出）**隐藏相应卡片**，改为呈现该物种有意义的指标（如"距上次换水"）。

## 9. 待确认问题（Open Questions）

1. **隐藏的粒度**：确认"按宠物隐藏"（本 PRD 建议）还是"按物种全局隐藏"？两者对多只同种宠物的体验不同。
2. **"计时"的准确含义**：现状只有手填 `durationMin`，**并无自动计时器**。决策 ③ 是否确认要**新建"开始→结束自动计时"交互**（P1-3），还是本次仅需把手填时长字段推广到更多事件即可？
3. **自动计时的适用范围**：仅"外出/放风"类（`walk`/`flight`），还是也含 `play`（玩耍/逗猫棒）、`sunbask`（晒太阳/晒灯）？
4. **同一宠物能否并行多段计时**（同时"遛鸟"又"出笼飞"）？还是同时只允许一个进行中的计时？
5. **自定义事件范围**：确认仅 `other` 物种可自定义（本 PRD 遵此），还是所有物种都应允许自定义？自定义事件是否需要支持"计时"？
6. **删除自定义事件的策略**：确认"保留历史 + 渲染兜底（本 PRD 建议）"，还是提供"连历史一起删"的选项？删除后历史记录希望显示成什么（原名 / "已删除的自定义事件"）？
7. **`other` 物种的兜底**：确认 §7.3 的 A/B 方案——"其他"是否保留通用池兜底，以照顾老 `kind:'other'` 用户不丢按钮？
8. **计时的最小粒度与展示**：时长单位与取整（分钟？秒级？），以及是否需要在统计里累计"总时长/平均时长"。
9. **物种 emoji 归属**：物种 emoji（选择器用）与宠物头像 emoji 的区分是否符合预期？"其他"物种默认 emoji 用 ❓ 还是 🐾？
10. **换物种后的配置**：某宠物从"狗"改为"猫"后，其按 petId 的隐藏/自定义配置如何处理（保留 / 清理 / 提示）？
